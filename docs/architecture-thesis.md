# OpenSoul 架构纲领：记忆×知识×技能×进化融合体

> **核心定位**：不做"单纯的记忆层"，也不做"单纯的知识库"——做两者的融合体，
> 加上技能遗传与自我进化。这是市面上还没有人做透的位置，是OpenSoul的差异化主线。
>
> 纲领确立时间：2026-09-19（用户拍板）

---

## 一、市面现状与判断（2026-09调研数据）

### 1.1 品类分开的现状

| 品类 | 代表产品 | 管什么 | 检索形态 |
|------|---------|--------|---------|
| 知识库（RAG） | Dify、RAGFlow、AnythingLLM、FastGPT | "世界是什么样的"——外部事实：文档、规范、资料 | 无状态：query→检索→上下文 |
| 记忆系统 | Mem0(41k★)、Zep/Graphiti(24k★)、Letta、Cognee | "我们之间发生过什么"——交互沉淀：偏好、决策、教训 | 有生命周期：蒸馏、更新、遗忘 |

市面上两者分开是商业和团队分工的结果，不是技术约束。
使用者角度：agent回答一个问题，需要知识库（客观事实）+记忆（历史教训）+技能（标准流程）三者协同——现在散落三个地方，agent自己拼。

### 1.2 融合趋势信号（调研依据）

- **Cognee**：定位已改叫"memory control plane"，知识图谱=知识+记忆混合体，70+公司生产部署（Bayer等），100万+管道/月
- **Membase**：明确"个人上下文memory + Knowledge Wiki"两层放一个系统
- **Zep**：时序知识图谱=事实+时间记忆融合，LongMemEval 63.8%（时序查询最强）
- **判断**：市面都在往融合方向走，但没有人做透——**位置空着**

### 1.3 认知科学依据

人类大脑不区分"知识"和"记忆"——语义记忆（facts）和情景记忆（episodes）在同一海马体-皮层系统中互相激活。查技术问题时，想起的不只是文档内容，还有"上次这么做翻车了"的教训。分开的系统做不到交叉激活。

## 二、融合的具体机制（OpenSoul设计方向）

### 2.1 统一存储与检索

- 知识（文档chunk+embedding）与记忆（蒸馏事实+embedding）同一向量库
- 一次query两边都搜，按**相关性+新鲜度+重要性**统一排序
- unified search已有骨架（9子系统并行检索），向量层是补齐项

### 2.2 记忆×知识交叉增强（双向）

- **记忆给知识库加权**：同一query，不同用户历史→不同排序（个性化检索）
- **知识库给记忆grounding**：dream蒸馏提炼经验时对照知识库，区分"用户偏好"（记忆）与"客观事实"（知识）
- **检索结果互相引用**：记忆命中→关联依据文档；知识命中→叠加"你上次用这个方案的结果"

### 2.3 统一生命周期

- 知识会过时（文档更新），记忆会衰减（不再相关）——同一个老化机制管理两者
- dream蒸馏扩展：蒸馏对话记忆之外，蒸馏"哪些知识被反复引用/哪些知识过时"——知识库有新陈代谢

### 2.4 融合体的独特闭环（主流系统没有的）

```
记忆（hippo）→ 技能（gene，程序性记忆）→ 遗传（heredity）→ 进化（evo）
```

Mem0/Cognee是记忆层，不管技能遗传和自我进化。这个闭环是OpenSoul区别于所有记忆/知识库产品的**核心差异**。

### 2.5 诚实提醒：融合≠混为一谈

- **知识**：相对静态的chunk，需要版本、引用溯源、权威性
- **记忆**：动态原子事实，需要个性化、user隔离、衰减
- 融合难点在**统一检索排序**（两者权重逻辑不同），不是简单放进一个库里

## 三、当前差距（2026-09-19实测数据）

| 项 | 现状 | 差距 |
|----|------|------|
| 向量层 | qdrant服务未运行（inactive） | semantic_search空转——主流系统标配底座 |
| 全文检索 | meilisearch管道已通（commit bc3a5619，39文档索引） | ✅ 仅此一项达标 |
| RAG管道 | knowledge_chunks=0行 | 文档→分块→嵌入→引用管道不存在 |
| 三因子检索 | hippo只有时间衰减 | recency+importance+relevance未实现（generative-agents方案约40行） |
| 检索质量 | 零benchmark | Mem0有LOCOMO 67.13%/p95 0.2s，OpenSoul无任何数字 |
| 知识数据 | ~/wiki 652个md未导入 | 用户决策：等opensoul成熟后启用 |
| 记忆数据 | LTM 472条（episodic 353+semantic 119）真实聊天产出 | dream蒸馏管道刚通，本地LLM硬件限制待provider配置 |
| 生产成熟度 | 39条测试数据+个人项目 | vs Mem0：AWS独家供应商/SOC2/1400万下载 |

**一句话结论**：融合的架构跑在半空转的地基上。基础工程补齐后，融合路线才是真的差异化。

## 四、工程路线

### 第一阶段：地基（融合的前提）

1. qdrant启动+嵌入管道接线——向量层活起来
2. RAG分块管道——knowledge_chunks从0到有
3. hippo三因子检索（recency+importance+relevance，generative-agents方案）
4. LOCOMO基准测试——先有检索质量数字，"好不好"才有答案
5. 知识库启用（等用户发话）：~/wiki 652md导入+索引（只建引用不复制文件）

### 第二阶段：融合增强

6. 统一检索排序：知识chunk+记忆事实混合排序（相关性+新鲜度+重要性）
7. 交叉增强：记忆检索关联知识依据，知识检索叠加历史教训
8. dream蒸馏扩展：知识使用模式蒸馏
9. 统一生命周期：知识过时+记忆衰减同一老化机制

### 第三阶段：融合体完整能力

10. 记忆→技能→遗传→进化闭环的端到端验证
11. 融合检索的个性化排序
12. benchmark对比：vs Mem0（记忆单项）/vs Dify（知识库单项）——融合体验优势量化
